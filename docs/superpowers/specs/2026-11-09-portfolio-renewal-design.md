# BKLimpf 포트폴리오 리뉴얼 설계

작성일: 2026-11-09
대상 사이트: https://www.bklimportfolio.com/ (Vercel 프로젝트 `bklimpf-portfolio`)

## 1. 목적

지금 사이트는 내용은 충분하지만 포트폴리오로서 "재미없고 심심하다". 특히 메인 화면 배경이 밋밋하다.
목표는 디자이너(UX/UI · 웹 · 그래픽)의 포트폴리오를 처음 연 사람이 **"전문적이면서 임팩트 있다"**고 느끼게 하는 것이다.
방법은 모션 그래픽과 인터랙션을 더하는 것이고, 기존 브랜드 톤(밝은 웜그레이 배경, 브라운 로고, 브라운 버튼)은 유지한다.

## 2. 목표 / 비목표 / 실패 기준

**목표**
- 메인 화면: 로고를 중심으로 한 시네마틱 인트로와 마우스 인터랙션
- 포트폴리오 목록: 기존 바둑판형은 유지하고, 간격을 좁히고 오버 효과를 정돈
- 상세 페이지: 기존 구조(이미지 세로 나열)는 유지하고 진입·스크롤 모션을 추가
- 사이트 전체에 같은 모션 언어(부드러운 ease-out, 아래에서 올라오는 등장)를 적용

**비목표**
- 콘텐츠(프로젝트 이미지, 문구) 재작성. 단, 명백한 오탈자는 예외(8절 참고)
- 프레임워크 도입이나 빌드 도구 추가. 지금처럼 정적 HTML/CSS/바닐라 JS로 유지
- 배포 자동화

**실패 기준 (동작은 해도 이러면 실패)**
- 로고가 흐리거나 깨져 보임
- 효과가 과해서 복잡하거나 촌스러워 보임. 사용자가 강한 그라데이션, 금색, 뿌연 블러, 과한 무채색을 명시적으로 거부했다
- 썸네일이 한꺼번에 너무 많이 쏟아짐
- 작업물 이미지가 작아지거나 가려져서 안의 글자가 안 읽힘

## 4. 메인 화면 (확정)

참고 구현: `.superpowers/brainstorm/202-1794200095/content/hero-a-v5.html` (최종 승인본)

- **배경**: 기존 `style.css`의 `.hero-section` 배경 레이어를 그대로 쓴다

  - inset 그림자

  - 원본: `https://static.wixstatic.com/media/cf309e_a8a7f28cb04643eaa3a285267d0667de~mv2.png`, 2000×1035
  - 가장자리가 깨지지 않도록 LANCZOS로 미리 줄인 파일을 쓴다: 가운데 로고용 `logo-1000.png`(1000px), 메뉴용 `logo-160.png`(160px). 실제 표시 크기의 2배 이상
  - 로고에는 3D transform, blur, opacity 애니메이션을 걸지 않는다(선명도 우선)
  - 크기: 화면 너비의 39.6%(시안 기준). 처음 44%에서 사용자가 90%로 줄여 달라고 했다
- **인트로 (최초 로드 1회)**:
  1. 브라운 톤의 1.5px 라인과 작은 점(화살촉)이 화면 왼쪽 끝에서 오른쪽 끝까지 화살대 높이를 따라 날아간다. 1.5초, easeInOutCubic
  2. 화살대 높이는 로고 원본 기준 y 497~520px, 중심 49.13%이고 픽셀 단위로 측정한 값이다. 라인 중심을 반드시 이 값에 맞춘다
  3. 화살촉의 x 위치와 로고 드러남(`clip-path: inset(0 X 0 0)`)을 프레임 단위로 동기화한다
  4. 지나간 뒤 라인은 사라지고, 1px 궤적선만 투명도 0.35로 화면 양끝까지 남는다
  5. 로고 위로 은은한 반짝임이 한 번 지나간다(흰색 22%, 1.8초)
  6. 이름("LIM BYUNG KWON", 작은 자간 넓은 글씨) → 직함("UX/UI · Website · Graphic Designer", 세리프 대문자) → **PDF Download 버튼** 순서로 각 줄이 자기 마스크 안에서 아래에서 올라온다. 지연 0 / 0.12 / 0.26초
  7. 상단 메뉴와 스크롤 표시가 페이드인한다
- **PDF 버튼**: 배경 `#4B3D39`, 흰 글씨 600, 오른쪽 "↓"
  - 호버 시 `#2f2523`가 왼쪽부터 채워지고(scaleX, 0.45초) 화살표가 2px 내려간다
  - 링크: `./portfolio.pdf` download
- **마우스 인터랙션 (인트로가 끝난 뒤에만)**:
  - 커서 위치에 흰 빛(radial, 흰색 55%)이 관성(lerp 0.08)을 두고 따라온다
  - 로고 모양 안에 은은한 빛 반사(soft-light)가 커서 쪽으로 움직인다
  - **썸네일 트레일**:
    - 썸네일은 정사각형이고 화면 너비의 9.5%, 로고 **뒤**(z-index가 로고보다 낮음)에 나타난다
    - 생성 조건: 직전 생성 위치에서 hero 너비의 5% 이상 이동했고, 직전 생성 후 350ms 이상 지났을 때. 사용자가 "붙어서 나오되 개수는 적게"를 원했다
    - 동시에 보이는 썸네일은 최대 3개. 4번째가 생기면 가장 오래된 것부터 사라진다
    - 등장: blur 2px→0을 0.4초, opacity 0.7초, translateY 14px→0과 scale 0.86→1을 1.6초 `cubic-bezier(.16,1,.3,1)`. 회전은 ±4도 랜덤
    - 1.1초 머문 뒤 1.2~1.4초에 걸쳐 아래로 가라앉으며 사라진다
    - 순서는 `imageUrls` 순서대로 순환한다. 썸네일은 Wix 축소판(`/v1/fill/w_300,h_300,al_c,q_80/thumb.jpg`)을 쓰고 미리 로드한다
    - PDF 버튼 위에서는 생성하지 않는다
  - **커스텀 커서**: 기본 포인터를 숨기고 링(28px)과 점을 표시한다. 옆에 방금 나타난 프로젝트의 "NN / 20 제목" 라벨이 붙는다. 반투명 밝은 배경을 깔고, 커서가 오른쪽 28% 영역에 있으면 라벨을 커서 왼쪽으로 옮긴다
  - 이름과 직함에는 배경색 빛 번짐 text-shadow를 줘서 썸네일 위에서도 읽히게 한다
- **접근성**:
  - `prefers-reduced-motion: reduce`면 인트로를 건너뛰고 최종 상태로 보여준다
  - 터치 기기(`pointer: coarse`)에서는 커스텀 커서, 썸네일 트레일, 커서 조명을 끈다. 인트로는 유지한다

## 5. 포트폴리오 목록 (확정. 사용자 표현으로 "100% 마음에 들진 않지만 진행")

참고 구현: `.superpowers/brainstorm/202-1794200095/content/work-grid.html`, 2번 모드

- 정사각형 바둑판 그리드, 5열. 간격 4px(기존 8px). 반응형 열 수는 기존 규칙을 따른다(≤1280: 4열, ≤1024: 3열, ≤480: 2열)
- 섹션 제목 "Selected Work"(세리프)와 오른쪽 "20 PROJECTS"(모노)
- **스크롤 진입**: 타일이 translateY 18px→0, opacity 0→1로 순서대로 올라온다. 타일마다 40ms 지연. IntersectionObserver로 화면에 들어올 때 시작한다
- **호버 (포커스)**:
  - 다른 타일: 투명도를 **쓰지 않는다**(밝은 배경이 비쳐 뿌옇게 보였기 때문). 대신 `rgba(32,24,21,.42)` 어두운 막을 씌우고 `saturate(.8)`을 준다
  - 호버한 타일: 막 없이 scale 1.04
  - 아래쪽 그림자(`rgba(36,27,24,.82)`에서 투명까지)를 깐다
  - 번호(모노 10px)와 가는 선(22px, 왼쪽부터 그려짐)을 표시한다
  - 흰 제목(600, 13~17px)이 translateY 10px→0으로 올라온다
- 클릭 시 상세로 이동한다(6절 전환 포함)

- **헤더**: "PROJECT 08" → 큰 세리프 제목 → (정보 행, 9절 결정 대기) 순서로 각 줄이 마스크 안에서 올라온다
- **이미지**:
  - 기존 `htmlContent` 이미지를 최대 너비 900~1200px으로 세로 나열한다(간격 0)
  - 스크롤 진입 시 `clip-path: inset(12% 0 0 0)`→`inset(0)`과 translateY 40px→0을 1.1초 동안 준다. **blur는 쓰지 않는다**
- **이전/다음 이동**: 배포본의 **좌우 사이드 버튼을 유지**하고 새 톤으로 다시 스타일링한다
  - 좌우 고정 원형 버튼, 호버 시 미리보기 카드(썸네일과 "PREVIOUS / NEXT PROJECT"와 제목)가 미끄러져 나온다
  - 색: 원형 버튼은 밝은 반투명, 호버 시 `#4B3D39` 채움과 흰 화살표
  - 시안에 있던 하단 "다음 프로젝트 큰 글씨" 영역은 **넣지 않는다**(사용자 결정)
- **맨 아래**: "목록으로 돌아가기" 버튼(`#4B3D39`)
- 크로노오디세이처럼 이미지 밖 텍스트 블록이 있는 페이지는 기존 마크업을 유지하고, 같은 스크롤 등장 효과만 적용한다

## 9. 사용자 결정 (2026-11-09 확정)

1. **상세 페이지 정보 행을 넣는다.**
   - `projectsData` 각 항목에 선택 필드 `client`, `category`, `role`을 추가한다
   - 값이 없는 칸은 렌더링하지 않는다. 셋 다 없으면 행 전체를 숨긴다
   - 실제 정보는 아직 받지 못했다. 그래서 제목에서 확실히 알 수 있는 값만 채우고(예: BMW → client "BMW", 게임 타이틀 → category "Game"), `role`은 비워 둔다. 사용자가 나중에 `data.js`에서 채울 수 있게 한다(빌더 판단)
2. **상단 메뉴: Home · Portfolio · About** ("More" 삭제)
3. **"Fitters Studio"는 따로 추가하지 않는다.**
   - 배포본 1번 프로젝트 "Web & Brand by AI" 안에 Fitters Studio·OGD Market·Stockify 사례로 이미 들어 있다
   - 로컬에만 있던 단독 "Fitters Studio" 항목(이미지 파일도 없음)은 버린다
   - 프로젝트는 배포본 그대로 20개이고, 수 표기("NN / 20", "20 PROJECTS")는 배열 길이에서 계산한다
